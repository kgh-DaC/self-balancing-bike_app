# 바이크 통신 프로토콜

출처: `01.Arduino Code and Library/remote.ino`(원본), `03.Firmware/self_balancing_bike/`(현재 사용 펌웨어). 코드와 다르면 코드가 정답이다.

## 03.Firmware 변경점 (2026-10-18 확인)
- 보드레이트 **9600** (`Serial.begin(9600)`, HC-05 기본값). 원본 01은 115200. 웹 앱은 보드레이트 선택(기본 9600)을 제공한다.
- **통신 두절 failsafe**: 정상 프레임이 500ms 없으면 `steering_remote = speed_remote = 0`. 앱의 80ms 주기 전송이 이 타이머를 계속 갱신한다.
- **수신 에코**: 조이스틱 값이 바뀌면 `"J <joyX> <joyY>\r\n"`을 보낸다. 앱은 이것을 마지막 전송값과 비교해 "수신 확인" 표시에 쓴다.
- 파서: ETX로 끝난 프레임(`complete`)만 적용하고 `cmd[7]` 밖에는 쓰지 않는다(01의 범위 밖 쓰기 버그 수정).

## 링크
- UART 115200 baud (`Serial.begin(115200)`). 블루투스 모듈은 이 보레이트의 투명 시리얼 브리지여야 한다. 모듈 종류(BLE/클래식)는 코드로 확인되지 않으므로 사용자에게 확인한다.
- STX = 0x02, ETX = 0x03.

## 앱 → 바이크
| 종류 | 프레임 | 설명 |
|---|---|---|
| 조이스틱 | `STX + XXX + YYY + ETX` (8바이트) | X,Y = (값+200)를 3자리 ASCII. 값 범위 -100~100, 범위 밖이면 무시됨 |
| 버튼1 ON/OFF | `STX 'A' ETX` / `STX 'B' ETX` | 3바이트 |
| 버튼2 ON/OFF | `STX 'C' ETX` / `STX 'D' ETX` | 3바이트 |

- X: 조향. 데드존 ±10. 최종 부호는 X와 같다(이중 반전). 앱은 "오른쪽 = +"로 보내고 실제 방향은 실차로 확인한다.
- Y: 속도(서보2 구동, `1500 + speed_remote*7`). 펌웨어에 부호 반전은 없고 `speed_remote = Y*0.8`이다(분석 확인). 전진/후진의 물리 방향은 실차로 확인한다.
- 모든 바이트는 127 이하여야 한다(초과 시 수신 오류로 폐기).
- 파서는 `Serial.available()`이 있는 동안만 읽는 단순 구조다. 한 프레임을 쪼개 보내거나 너무 빠르게(<30ms) 보내면 깨질 수 있으므로 한 프레임을 한 번에 write하고 50~100ms 주기로 보낸다.

## 바이크 → 앱 (현재 코드에서는 `sendControlParameters()`가 호출되지 않음)
`STX + 버튼상태6자리 + 0x01 + "0" + 0x04 + "0" + 0x05 + "0" + ETX`. 필요하면 앱은 수신 파싱을 선택 기능으로 둔다.

## 디버그 모드 (주의)
`loop()`에서 `Tuning()`과 `readControlParameters()` 중 하나만 활성화한다. 원격 제어는 `readControlParameters()` 활성 상태에서만 동작한다. `Tuning()` 모드의 명령은 2바이트 `[파라미터][+/-]`(p,i,s,a,c)이며, 웹 앱의 선택 기능(튜닝 패널)으로 넣을 수 있으나 두 모드를 동시에 쓸 수 없음을 UI에 명시한다.

## 안전 규칙
1. 연결 직후와 해제/오류/탭 숨김/입력 해제 시 중립 `(0,0)` = `"200200"` 전송.
2. 바이크는 `vertical && calibrated`일 때만 구동한다. 캘리브레이션은 시리얼 `Tuning()` 모드의 `c`+/- 명령이므로 원격 모드에서는 불가함을 안내한다.
3. 조향/속도 입력은 UI에서 -100~100으로 클램프한 뒤 인코딩한다.

## 브라우저 연결
- Web Bluetooth: **BLE만** 지원. 일반 UART 서비스 `0000ffe0-...` / 특성 `0000ffe1-...`(HM-10 계열), Nordic UART `6e400001-b5a3-f393-e0a9-e50e24dcca9e`(TX 쓰기 `...0002...`).
- 클래식 SPP(HC-05/06): 먼저 페어링 → Web Serial(`navigator.serial`, 현재 펌웨어 9600)로 연결. `requestPort`에 `allowedBluetoothServiceClassIds: [SPP 00001101-…]`를 넣어 PC(가상 COM 포트)와 안드로이드 Chrome 137+(갤럭시 탭, 페어링한 HC-05 직접 선택) 모두 지원한다(2026-11-27). 안드로이드는 disconnect 이벤트가 없어 끊김은 수신 스트림 종료로 감지한다.
- 둘 다 HTTPS 또는 localhost 필요, Chrome/Edge 데스크톱·안드로이드 지원(iOS Safari 미지원).

## 분석으로 확인된 추가 사실
자세한 내용은 `_workspace/01_analyst_protocol.md` 참고. 버튼 A~D는 현재 펌웨어에서 효과 없음, 통신 두절 failsafe 없음(앱이 중립을 보내야 함), 현재 빌드는 Tuning()이 주석 처리되어 웹으로 캘리브레이션 불가, 모듈 종류와 UUID는 미검증.
